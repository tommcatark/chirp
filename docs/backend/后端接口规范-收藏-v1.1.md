# 后端接口规范 · 收藏（v1.1）

> 面向后端开发者的实现规格。前端「收藏页」与「首页帖子卡片收藏按钮」已完成并按本文契约调用；后端当前**没有**收藏功能，需要按本文补齐。
> 通用约定（网关入口、认证、分页 `PageResponse`、错误 `{"message":"..."}`、`Instant` 时间格式）见 `后端接口规范-探索通知消息-v1.1.md` §1，本文不重复。

---

## 0. 现状与改动清单

| 项 | 现状 | 需要做的事 |
|---|---|---|
| 收藏接口 | 不存在，`GET /api/bookmarks` 与 `POST/DELETE /api/posts/{id}/bookmark` 均返回 404 | 新增 3 个接口 |
| 数据库 | 无 `bookmarks` 表 | 新增表 + 外键 + 唯一约束 + 索引 |
| `PostResponse` | 无 `bookmarked` 字段 | 新增该字段（访客恒为 `false`） |
| 网关 | 无 `/api/bookmarks/**` 路由 | 新增路由 → `chirp-posts`（8082） |
| 前端 | 已完成 | 无需改动 |

前端表现：收藏页在接口返回 404 时显示「收藏功能暂未开放」提示；接口上线后自动恢复正常，不需要前端发版。

## 1. 数据模型

### 1.1 bookmarks 表

| 列 | 类型 | 约束 |
|---|---|---|
| id | BIGSERIAL | PK |
| user_id | BIGINT | NOT NULL，FK → users(id) ON DELETE CASCADE（收藏者）|
| post_id | BIGINT | NOT NULL，FK → posts(id) ON DELETE CASCADE（被收藏的帖子）|
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT now() |

约束与索引：

- `UNIQUE (user_id, post_id)` — 同一用户对同一帖子只能收藏一次，是幂等的基础。
- `idx_bookmarks_user_created (user_id, created_at DESC)` — 收藏列表按收藏时间倒序查询。
- `idx_bookmarks_post_id (post_id)` — 帖子删除/统计用。

> 帖子被删除时收藏记录随外键级联删除；不允许出现「收藏了一条已删除帖子」的情况。

## 2. 接口

### 2.1 POST /api/posts/{id}/bookmark — 收藏

**必须登录**（token 缺失/失效 → 401）。

- 帖子不存在 → `404 {"message":"帖子不存在"}`
- 幂等：已收藏时再次调用不报错、不重复插入。

**响应（200）**

```json
{"bookmarked": true}
```

实现要点：`insert ... on conflict do nothing`，或用唯一约束捕获后视为成功。

### 2.2 DELETE /api/posts/{id}/bookmark — 取消收藏

**必须登录**。

- 未收藏时调用 → 仍返回 200（幂等），不报错。
- 帖子不存在 → `404 {"message":"帖子不存在"}`（帖子已删除导致记录级联消失时，也可按幂等直接返回成功，前端两种都能正确处理）。

**响应（200）**

```json
{"bookmarked": false}
```

### 2.3 GET /api/bookmarks — 我的收藏列表

**必须登录**。访客调用 → 401（这是个人数据，不做匿名访问）。

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `offset` | int | 0 | 分页偏移 |
| `limit` | int | 20 | 每页条数，上限 50 |

**排序**：按收藏时间 `bookmarks.created_at DESC`（最近收藏在最前），**不是**按帖子发布时间。

**响应**：`PageResponse<PostResponse>`，元素与信息流帖子结构完全一致，且 `bookmarked=true`。

```json
{
  "items": [
    {
      "id": 12,
      "userId": 1,
      "authorName": "张三",
      "authorHandle": "zhangsan",
      "authorAvatarUrl": null,
      "content": "今天天气不错 #晴天#",
      "createdAt": "2026-10-23T08:00:00Z",
      "likes": 3,
      "reposts": 0,
      "comments": 1,
      "liked": false,
      "mine": false,
      "bookmarked": true
    }
  ],
  "total": 1, "offset": 0, "limit": 20, "hasMore": false
}
```

- `total` 为当前用户收藏总数，不受 `limit` 影响。
- `liked` / `mine` 仍需按当前用户正确计算。

## 3. PostResponse 新增字段

在现有 `PostResponse` 中新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| bookmarked | boolean | 当前请求者是否已收藏该帖子；**访客恒为 `false`**；`GET /api/bookmarks` 返回的元素恒为 `true` |

该字段需在所有返回帖子的接口中填充：`GET /api/posts`、`GET /api/search?type=post`、`GET /api/posts/{id}`、`GET /api/bookmarks`、以及发帖/评论等返回帖子的接口。

实现建议：按当前 `userId` 批量查询 `bookmarks` 中对应 `post_id` 集合（一次 `IN` 查询），避免逐条判断产生 N+1。

## 4. 网关路由

`chirp-gateway` 的 `application.yml` 需新增：

```yaml
        - id: chirp-bookmarks-route
          uri: http://localhost:8082
          predicates:
            - Path=/api/bookmarks/**
```

`/api/posts/**` 已有路由，`POST/DELETE /api/posts/{id}/bookmark` 无需新增路由。

## 5. 前端调用对照

| 页面/位置 | 调用 | 依赖字段 |
|---|---|---|
| `bookmarks.js` 列表 | `GET /api/bookmarks?offset=&limit=20` | `items`（`PostResponse`）、`total`、`hasMore` |
| `bookmarks.js` 取消收藏 | `DELETE /api/posts/{id}/bookmark` | 仅需 2xx |
| `home.js` 卡片收藏按钮 | `POST/DELETE /api/posts/{id}/bookmark` | 响应中的 `bookmarked`（布尔，可选；缺失时前端保留点击前的状态） |
| `home.js` 卡片初始状态 | `GET /api/posts` 的 `bookmarked` | `bookmarked` |

行为细节（后端无需关心，列在此处便于理解契约）：

- 收藏按钮点击为**乐观更新**，请求失败会静默回滚，因此后端返回非 2xx 时前端不会弹出错误提示。
- 收藏页取消收藏成功后立即从列表移除该卡片并递减计数，不重新拉取列表。

## 6. 验收用例

1. 张三收藏帖子 12 → 200 `{"bookmarked":true}`；再次收藏 → 仍 200，`bookmarks` 表中仍只有一条记录。
2. `GET /api/bookmarks` → 1 条，`items[0].id=12`，`bookmarked=true`，`total=1`。
3. 张三收藏帖子 13 后再次查询 → 帖子 13 排在帖子 12 之前（按收藏时间倒序，而非发帖时间）。
4. 取消收藏帖子 12 → 200 `{"bookmarked":false}`；列表只剩 1 条，`total` 同步为 1。
5. 重复取消收藏 → 仍 200，不报错。
6. 不存在的帖子 id → 404「帖子不存在」。
7. 无 token 调用三个接口 → 均 401。
8. 李四的收藏列表看不到张三的收藏（数据按 `user_id` 隔离）。
9. 删除帖子 12 → 张三的收藏记录级联删除，列表不再出现该条目，`total` 减 1；不产生 500 或孤立记录。
10. 访客调用 `GET /api/posts` → 每条 `bookmarked=false`；张三调用且已收藏帖子 12 → 该条 `bookmarked=true`，其余 `false`。
11. `GET /api/search?type=post` 返回的帖子同样正确填充 `bookmarked`。
12. 分页：收藏 25 条后 `limit=20` → 第一页 20 条 `hasMore=true`；`offset=20` → 5 条 `hasMore=false`；`total=25`。

## 7. 实现注意事项

1. 收藏对帖子作者**不产生通知**（产品未定义该行为，不要顺手加）。
2. `user_id` 必须来自 token 解析，禁止接受请求体中的用户 id。
3. 列表查询需 `JOIN posts` 一次性取帖子与作者信息，避免 N+1；注意帖子已删除时不应返回（`INNER JOIN` 天然满足）。
4. `UNIQUE (user_id, post_id)` 必须建在数据库层，不能只靠应用层「先查再插」，否则并发重复点击会产生重复行。
