## 2. 全局约定

### 2.1 请求与响应

| 项 | 约定 |
|---|---|
| Base URL | `http://localhost:8080/api` |
| 请求头 | `Content-Type: application/json`（有请求体时）、`Accept: application/json` |
| 字符编码 | UTF-8 |
| 字段命名 | camelCase |
| 时间 | ISO-8601 UTC，例 `2026-11-14T06:26:46.657430Z` |
| 可空字段 | 返回 `null` 或空字符串，不省略字段 |
| 计数字段 | 返回数字，无数据为 `0` |

### 2.2 鉴权

- 登录 / 注册成功后签发 **64 位十六进制随机字符串** token（32 字节 SecureRandom）。
- token 存储于 Redis：key `chirp:token:{token}`，value 为用户 ID，TTL `604800000 ms`（7 天）。
- 登出删除对应 Redis key，token 立即失效。
- 名为 `chirp.jwt.*` 的配置仅用于密钥与过期时间命名，**实际不是 JWT**。
- 网关 `JwtAuthGlobalFilter` 负责统一校验，并把用户 ID 写入下游请求头 `X-User-Id`。
- 网关放行规则：

| 规则 | 说明 |
|---|---|
| `OPTIONS` | 全部放行 |
| `/api/auth/**` | 注册、登录、公钥、忘记密码 |
| `GET /api/posts/**` | 信息流、帖子详情、评论列表 |
| `GET /api/users/{数字id}` | 公开资料 |
| `GET /api/users/{id}/posts`、`/followers`、`/following` | 公开列表 |
| `GET /api/search` | 搜索 |
| `GET /api/hashtags/**` | 话题趋势 |
| `/actuator/**` | 健康检查 |

- 其余 `/api/**` 必须携带 `Authorization: Bearer <token>`。
- 401 响应体：

```json
{ "message": "缺少登录凭证，请先登录" }
```

```json
{ "message": "登录已失效，请重新登录" }
```

- 公开 GET 接口如果携带 token，会返回与当前用户相关的 `liked` / `mine` / `bookmarked` / `followedByMe`。

### 2.3 错误响应

- 控制器内业务错误统一返回：

```json
{ "message": "中文原因" }
```

- 状态码：400 参数/业务拒绝，401 未登录，403 越权，404 不存在，409 冲突，500 服务异常。
- **实现偏差**：项目没有全局异常处理器。Bean Validation（`@Valid`）失败时返回 Spring 默认结构，不含 `message`：

```json
{ "timestamp": "2026-11-14T08:49:53.565+00:00", "status": 400, "error": "Bad Request", "path": "/api/auth/register" }
```

- **实现偏差**：部分删除接口在 401 / 403 / 404 时返回空响应体（无 `message`），见第 7 章。

### 2.4 分页

请求参数：

| 参数 | 默认 | 约束 |
|---|---|---|
| `offset` | `0` | ≥ 0 |
| `limit` | 各接口不同（20 / 30） | 服务端夹取到 1–50 |

响应包装（帖子、评论、用户、通知、私信、收藏）：

```json
{
  "items": [],
  "total": 123,
  "offset": 0,
  "limit": 20,
  "hasMore": true
}
```

- `hasMore = offset + items.length < total`。
- 例外：`GET /api/hashtags/trending` 返回裸数组；`GET /api/messages/conversations` 返回 `{items, totalUnread}`，不分页。

### 2.5 长度与校验

| 字段 | 规则 |
|---|---|
| 帖子 `content` | 1–500 码点；控制器按 `codePointCount` 校验 |
| 评论 `content` | 1–500 码点 |
| 昵称 `name` | 2–120 码点 |
| 简介 `bio` | 0–200 码点 |
| 头像 `avatarUrl` | 0–500 字符 |
| 密码明文 | 8–100 字符（RSA 解密后） |
| 私信 `content` | 1–500（Java `String.length()`） |

- **实现偏差**：DTO 上的 `@Size` 会先于控制器按 UTF-16 长度执行；emoji 等多码元字符可能先触发默认 400，而不是控制器的中文 `message`。

## 3. 数据结构

### 3.1 `AuthResponse`

```json
{
  "token": "3f8a1c9e4b7d2f6a0e5c8b1d4a7f9e2c6b3d8a1f4e7c0b5d9a2f6e3c8b1d4a7f",
  "expiresAt": "2026-11-21T06:26:46.657430Z",
  "id": 8,
  "name": "设计测试",
  "email": "designer@chirp.test",
  "handle": "designer",
  "avatarUrl": null,
  "message": "登录成功"
}
```

### 3.2 `PageResponse<T>`

```json
{ "items": [], "total": 14, "offset": 0, "limit": 50, "hasMore": false }
```

### 3.3 `PostResponse`

```json
{
  "id": 14,
  "userId": 1,
  "authorName": "张三",
  "authorHandle": "zhangsan",
  "authorAvatarUrl": "",
  "content": "今天的日落值得一条头条",
  "createdAt": "2026-10-11T14:45:01.749446Z",
  "likes": 1,
  "reposts": 0,
  "comments": 1,
  "liked": false,
  "mine": false,
  "bookmarked": false
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `reposts` | number | 当前恒为 `0`，前端不渲染转发 |
| `liked` | boolean | 未登录恒为 `false` |
| `mine` | boolean | 未登录恒为 `false` |
| `bookmarked` | boolean | 未登录恒为 `false` |
| `authorAvatarUrl` | string \| null | 可能为 `null` 或空字符串 |

### 3.4 `CommentResponse`

```json
{
  "id": 88,
  "postId": 14,
  "userId": 4,
  "authorName": "李四",
  "authorHandle": "lisi",
  "authorAvatarUrl": null,
  "content": "同意，今天的晚霞也是",
  "createdAt": "2026-11-14T03:10:00Z",
  "mine": false
}
```

### 3.5 `UserResponse` / `UserMeResponse`

公开资料：

```json
{
  "id": 3,
  "name": "张三",
  "handle": "zhangsan",
  "bio": "写字的人",
  "avatarUrl": null,
  "createdAt": "2026-10-01T08:00:00Z",
  "postCount": 12,
  "followingCount": 5,
  "followerCount": 20,
  "followedByMe": false,
  "me": false
}
```

`/users/me` 额外返回 `email`，且 `followedByMe=false`、`me=true`。

### 3.6 通知

```json
{
  "id": 5,
  "type": "like",
  "actor": { "id": 4, "name": "李四", "handle": "lisi", "avatarUrl": null },
  "postId": 14,
  "postExcerpt": "今天的日落值得一条头条",
  "commentId": null,
  "commentExcerpt": null,
  "isRead": false,
  "createdAt": "2026-11-14T03:20:00Z"
}
```

通知分页响应在标准包装上追加 `unreadCount`：

```json
{ "items": [], "total": 30, "offset": 0, "limit": 20, "hasMore": true, "unreadCount": 3 }
```

### 3.7 私信

```json
{
  "id": 1,
  "senderId": 3,
  "recipientId": 4,
  "content": "你好",
  "isRead": false,
  "createdAt": "2026-11-14T03:30:00Z"

```

## 4. 接口详情

### 4.1 认证 `chirp-auth`

#### 4.1.1 `GET /api/auth/public-key`

- 鉴权：否
- 响应 200：`{ "publicKey": "<SPKI DER Base64>" }`
- 用途：前端以 RSA-OAEP(SHA-256) 加密密码。
- 注意：认证服务重启会重新生成密钥对，前端需重新拉取。

#### 4.1.2 `POST /api/auth/register`

- 鉴权：否
- 请求体：`{ "name": "张三", "email": "a@b.com", "password": "<RSA 密文>" }`
- 响应 201：`AuthResponse`，`message="注册成功"`
- 错误：
  - 400：解密失败或密码长度不在 8–100，`{"message":"无效的请求，请刷新页面后重试。"}`
  - 400：昵称 / 邮箱 `@Valid` 失败（Spring 默认结构）
  - 409：邮箱已注册，`{"message":"该邮箱已经注册"}`
- 行为：注册成功即写入 Redis token，前端无需二次登录。

#### 4.1.3 `POST /api/auth/login`

- 鉴权：否
- 请求体：`{ "email": "a@b.com", "password": "<RSA 密文>" }`
- 响应 200：`AuthResponse`，`message="登录成功"`
- 错误：
  - 401：邮箱或密码错误，`{"message":"邮箱或密码不正确"}`
  - 400：密文无法解密，`{"message":"无效的请求，请刷新页面后重试。"}`

#### 4.1.4 `POST /api/auth/logout`

- 鉴权：是
- 请求体：无
- 响应 204：无响应体
- 行为：删除当前 Bearer token 的 Redis 记录；幂等。

#### 4.1.5 `POST /api/auth/forgot-password`

- 鉴权：否
- 请求体：`{ "email": "a@b.com" }`
- 响应 200：`{ "message": "如果该邮箱已注册，重置密码的链接将发送到你的邮箱。" }`
- 说明：本期不真实发信。

### 4.2 用户 `chirp-users`

#### 4.2.1 `GET /api/users/me`

- 鉴权：是
- 响应 200：`UserMeResponse`
- 错误：401

#### 4.2.2 `PUT /api/users/me`

- 鉴权：是
- 请求体（字段均可选，只更新传入项）：

```json
{ "name": "张三丰", "bio": "写字的人", "avatarUrl": "https://example.com/a.png" }
```

- 响应 200：`UserMeResponse`
- 错误：
  - 400 昵称不在 2–120：`昵称需要 2-120 个字符`
  - 400 简介超 200：`简介不能超过 200 个字符`
  - 400 头像链接超 500：`头像链接过长`
  - 400 三字段都未传：`没有需要更新的内容`
- 约束：邮箱与密码不可通过此接口修改。

#### 4.2.3 `GET /api/users/{id}`

- 鉴权：否（可带 token）
- 响应 200：`UserResponse`
- 错误：404 `{"message":"用户不存在"}`

#### 4.2.4 `GET /api/users/{id}/posts`

- 鉴权：否（可带 token）
- 参数：`offset` / `limit`（默认 20，上限 50）
- 响应 200：`PageResponse<PostResponse>`，按 `createdAt` 倒序
- 错误：404 `用户不存在`

#### 4.2.5 `POST /api/users/{id}/follow`

- 鉴权：是
- 响应 200：`{ "following": true, "followerCount": 21 }`
- 错误：
  - 400 `不能关注自己`
  - 404 `用户不存在`
- 幂等：已关注时重复调用不报错。
- 副作用：向 Kafka 发布 `follow` 通知事件。

#### 4.2.6 `DELETE /api/users/{id}/follow`

- 鉴权：是
- 响应 200：`{ "following": false, "followerCount": 20 }`
- 错误：404 `用户不存在`
- 幂等：未关注时取消不报错；不回溯删除历史通知。

#### 4.2.7 `GET /api/users/{id}/followers`

- 鉴权：否（可带 token）
- 参数：`offset` / `limit`（默认 20，上限 50）
- 响应 200：`PageResponse<UserResponse>`，按关注时间倒序
- 错误：404 `用户不存在`

#### 4.2.8 `GET /api/users/{id}/following`

- 鉴权：否（可带 token）
- 参数与响应同 4.2.7

### 4.3 帖子与互动 `chirp-posts`

#### 4.3.1 `GET /api/posts`

- 鉴权：`latest` 否；`following` 是
- 参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `scope` | `latest` | `latest` / `following` |
| `offset` | `0` | 分页偏移 |
| `limit` | `20` | 夹取到 1–50 |

- 响应 200：`PageResponse<PostResponse>`，按 `createdAt` 倒序
- 错误：401 `following` 未登录
- 说明：`limit=999` 实际按 50 返回（已验证）。

#### 4.3.2 `POST /api/posts`

- 鉴权：是
- 请求体：`{ "content": "今天的日落值得一条头条" }`
- 响应 201：`PostResponse`
- 错误：
  - 400 空内容 / 超 500（`@Valid` 默认结构）
  - 401 `登录已失效，请重新登录`
- 身份：作者由 token 解析，请求体不含 `userId`。

#### 4.3.3 `GET /api/posts/{id}`

- 鉴权：否（可带 token）
- 响应 200：`PostResponse`，含 `liked` / `mine` / `bookmarked`
- 错误：404 `帖子不存在`
- 说明：前端当前未使用该接口。

#### 4.3.4 `DELETE /api/posts/{id}`

- 鉴权：是
- 响应 204：无响应体
- 错误：
  - 401：空响应体（网关拦截时才有 JSON）
  - 403：非作者，空响应体
  - 404：不存在，空响应体
- 级联：评论、点赞、收藏随帖子删除；通知的 `post_id` 置 NULL。

#### 4.3.5 `POST /api/posts/{id}/like`

- 鉴权：是
- 响应 200：`{ "liked": true, "likes": 6 }`
- 错误：404 `帖子不存在`
- 幂等：重复点赞不报错，返回最新计数。
- 副作用：非本人帖子发布 `like` 通知事件。

#### 4.3.6 `DELETE /api/posts/{id}/like`

- 鉴权：是
- 响应 200：`{ "liked": false, "likes": 5 }`
- 错误：404 `帖子不存在`
- 幂等：未点赞时取消不报错。

#### 4.3.7 `POST /api/posts/{id}/bookmark`

- 鉴权：是
- 响应 200：`{ "bookmarked": true }`
- 错误：404 `帖子不存在`
- 幂等：重复收藏不报错。

#### 4.3.8 `DELETE /api/posts/{id}/bookmark`

- 鉴权：是
- 响应 200：`{ "bookmarked": false }`
- 错误：404 `帖子不存在`
- 幂等：未收藏时取消不报错。

#### 4.3.9 `GET /api/posts/{id}/comments`

- 鉴权：否（可带 token）
- 参数：`offset` / `limit`（默认 20，上限 50）
- 响应 200：`PageResponse<CommentResponse>`，按 `createdAt` **升序**
- 错误：404 `帖子不存在`

#### 4.3.10 `POST /api/posts/{id}/comments`

- 鉴权：是
- 请求体：`{ "content": "同意，今天的晚霞也是" }`
- 响应 201：`CommentResponse`
- 错误：
  - 400 空内容 / 超 500（`@Valid` 默认结构）
  - 404 `帖子不存在`
- 副作用：非本人帖子发布 `comment` 通知事件。

#### 4.3.11 `DELETE /api/comments/{id}`

- 鉴权：是
- 响应 204：无响应体
- 错误：
  - 401：空响应体
  - 403：非作者，空响应体
  - 404：不存在，空响应体
- 级联：通知的 `comment_id` 置 NULL。

### 4.4 发现 `chirp-posts`

#### 4.4.1 `GET /api/search`

- 鉴权：否（可带 token）
- 参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `q` | 是 | 关键词；`trim` 后为空返回 400 |
| `type` | 是 | `post` 或 `user` |
| `offset` | 否 | 默认 0 |
| `limit` | 否 | 默认 20，上限 50 |

- 响应 200：`PageResponse<PostResponse>` 或 `PageResponse<UserResponse>`
- 错误：
  - 400 `{"message":"搜索关键词不能为空"}`
  - 400 `{"message":"搜索类型不合法"}`
  - 缺少 `q` / `type`：Spring 默认 400 结构
- 说明：帖子按正文 ILIKE 匹配；用户按昵称 ILIKE 匹配。

#### 4.4.2 `GET /api/hashtags/trending`

- 鉴权：否
- 参数：`limit`，默认 5，夹取到 1–20
- 响应 200：裸数组

```json
[ { "tag": "秋日鸣响", "postCount": 12 }, { "tag": "产品更新", "postCount": 8 } ]
```

- 统计范围：最近 200 条帖子，按 `#tag#` 或 `#tag`（后接空白/结尾）提取，按出现次数倒序。

#### 4.4.3 `GET /api/bookmarks`

- 鉴权：是
- 参数：`offset` / `limit`（默认 20，上限 50）
- 响应 200：`PageResponse<PostResponse>`，按收藏时间倒序，`bookmarked=true`
- 错误：401
- 说明：帖子被删除后不会出现在 items 中，可能出现 `items.length < limit` 但 `total` 仍按收藏记录统计。

### 4.5 通知 `chirp-social`

#### 4.5.1 `GET /api/notifications`

- 鉴权：是
- 参数：`offset` / `limit`（默认 20，上限 50）
- 响应 200：`NotificationPageResponse`（标准分页 + `unreadCount`），按 `createdAt` 倒序
- `unreadCount`：当前用户全部未读数，不受分页影响。

#### 4.5.2 `POST /api/notifications/read`

- 鉴权：是
- 请求体（可选）：

```json
{ "ids": [1, 2, 3] }
```

- 不传、`{}`、`null` 或空数组：全部标记已读。
- 响应 200：`{ "unreadCount": 0 }`（剩余未读数）
- 幂等：重复标记不报错。

### 4.6 私信 `chirp-social`

#### 4.6.1 `GET /api/messages/conversations`

- 鉴权：是
- 响应 200：`ConversationsResponse`

```json
{
  "items": [
    {
      "user": { "id": 4, "name": "李四", "handle": "lisi", "avatarUrl": null },
      "lastMessage": { "id": 10, "senderId": 4, "recipientId": 8, "content": "在吗", "isRead": false, "createdAt": "2026-11-14T03:30:00Z" },
      "unreadCount": 2
    }
  ],
  "totalUnread": 2
}
```

- 说明：不分页；按最后一条消息时间倒序；`unreadCount` 为当前用户在该会话的未读数。

#### 4.6.2 `GET /api/messages`

- 鉴权：是
- 参数：

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `with` | 是 | — | 对方用户 ID |
| `offset` | 否 | 0 | 分页偏移 |
| `limit` | 否 | 30 | 上限 50 |

- 响应 200：`PageResponse<MessageResponse>`，按 `createdAt` **倒序**（最新在前，前端反转后展示）
- 错误：404 `用户不存在`
- 说明：缺少 `with` 返回 Spring 默认 400。

#### 4.6.3 `POST /api/messages`

- 鉴权：是
- 请求体：

```json
{ "recipientId": 4, "content": "你好" }
```

- 响应 201：`MessageResponse`
- 错误：
  - 400 缺少接收者：`缺少接收者`
  - 400 内容为空或超 500：`消息内容需为 1-500 字符`
  - 400 给自己发：`不能给自己发消息`
  - 404 接收者不存在：`用户不存在`

#### 4.6.4 `POST /api/messages/read`

- 鉴权：是
- 请求体：`{ "with": 4 }`
- 响应 200：`{ "unreadCount": 1 }`（当前用户全部未读私信数）
- 错误：400 `缺少会话对象`

#### 4.6.5 `GET /api/messages/unread-count`

- 鉴权：是
- 响应 200：`{ "unreadCount": 3 }`

## 5. 副作用与异步通知

- Kafka 主题：`chirp.notifications`；消费组：`chirp-social-notification`。
- 生产：`chirp-posts`（点赞、评论）、`chirp-users`（关注）。
- 消费：`chirp-social` 异步落库生成通知。
- 通知类型：`like` / `comment` / `follow`。
- 自己给自己点赞 / 评论不产生通知；关注自己返回 400。
- 通知摘要截取前 50 个字符。
- 帖子删除：评论、点赞、收藏级联删除；通知 `post_id` 置 NULL。
- 评论删除：通知 `comment_id` 置 NULL。
- 取关不删除历史 follow 通知。
- 通知写入为异步，存在秒级延迟；前端角标与列表以接口返回为准。

## 6. 与 v1.0 的差异

| 项 | v1.0 | v1.1 实际 |
|---|---|---|
| Token 存储 | DB `tokens` 表 | Redis `chirp:token:{token}`，TTL 7 天 |
| 接口数量 | 25 | 34（+收藏 3、私信 5、话题趋势 1） |
| `PostResponse` | 无收藏字段 | 追加 `bookmarked` |
| 收藏 | 无 | `POST/DELETE /posts/{id}/bookmark`、`GET /bookmarks` |
| 私信 | 无 | 会话、消息、发送、已读、未读数 5 个接口 |
| 话题趋势 | 无 | `GET /hashtags/trending` |
| 公开接口 | 少量 GET | 扩展帖子、评论、用户资料、搜索、话题趋势等 GET |
| 通知未读数 | 规划 | 已实现 `unreadCount` 与标记已读 |
| 错误格式 | 全部 `{message}` | 业务错误是；`@Valid` 与部分删除接口不是 |
| `reposts` | 待确认 | 保留字段，恒为 0 |
| `type=all` 搜索 | 不需要 | 未实现，前端并发两次请求 |

## 7. 已知偏差与待办

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| B1 | 无全局异常处理器，`@Valid` 失败返回 Spring 默认结构 | 前端取不到 `message` | 增加 `@RestControllerAdvice` 统一错误体 |
| B2 | 部分删除接口 401/403/404 返回空响应体 | 前端只能按状态码判断 | 统一返回 `{message}` |
| B3 | `authorAvatarUrl` 可能为 `null` 或 `""` | 前端需同时兼容 | 统一空值为 `null` |
| B4 | `@Size` 先于 `codePointCount` | emoji 场景错误文案不一致 | 统一按码点校验 |
| B5 | 私信长度用 `String.length()` | 与帖子/评论的码点规则不一致 | 统一码点 |
| B6 | 收藏列表 `items` 会过滤已删除帖子 | `items.length` 可能小于 `total` | 文档化或改为清理收藏记录 |
| B7 | 话题趋势只扫描最近 200 条帖子 | 老话题可能不再出现 | 增加话题索引或统计表 |
| B8 | 用户帖子列表逐条查作者（N+1） | 数据量大时性能下降 | 批量查询作者 |
| B9 | `tokens` 表仍存在但认证已改用 Redis | 结构冗余 | 清理或恢复 DB token |
| B10 | 无接口限流 | 登录/发帖可被高频调用 | 网关或服务层限流 |
| B11 | 前端未使用 `GET /posts/{id}` | 详情能力闲置 | 可用于帖子详情页 |
