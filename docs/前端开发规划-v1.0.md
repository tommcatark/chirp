## 阅读指南

- 本文档是前端开发的执行清单，**按阶段顺序推进，每个阶段独立可验收**。
- 职责边界：**前端不修改任何后端代码**。所有后端需求以《后端接口规范 v1.0》交付，本文档第 5 章只列出「前端依赖后端什么」，不构成对后端的任务分配。
- 标记含义：
  - `[无]` 该步骤不依赖任何后端接口，可立即开工
  - `[改造]` 依赖后端对已有接口做调整
  - `[新增]` 依赖后端提供尚不存在的接口
- 术语：**mock 层** = 前端内置的假接口实现，用于在后端未就绪时跑通全链路；**真接口** = 后端实际提供的 HTTP 接口。

## 1. 项目现状快照（2026-10-09）

### 1.1 技术栈

| 层 | 现状 |

## 2. 前置约定（来自设计文档 5.2 / 9 / 10）

| 项 | 约定 |
|---|---|
| 技术栈 | 原生 HTML/CSS/JS 多页面，零构建，不引框架；交互复杂度显著上升后再评估 Vue/React |
| 文件组织 | 一页一 `html` + 一同名 `js`；公共能力只进 `shared.js`，页面内不重复实现 |
| 渲染安全 | 所有用户输入必须过 `escapeHTML`，禁止 innerHTML 直插未转义数据 |
| 鉴权 | 写操作一律带 `Authorization: Bearer <token>`；401 清 storage → 跳 `/index.html?next=<当前页>` |
| 校验 | 前端校验只是体验层，后端为准；错误文案取响应体 `message` 字段，不自行翻译或拼接 |
| 分页 | `offset + limit`，默认 20、最大 50 |
| 错误码 | 400 参数 / 401 未登录 / 403 越权 / 404 不存在 / 409 冲突 / 500 服务异常 |
| 命名 | 常量 `UPPER_SNAKE`、函数 `camelCase`、DOM id `kebab-case` |
| 注释 | 关键功能与关键技术写中文注释（沿用后端规范） |
| CSP | 沿用 `server.mjs` 现有策略；**仅当新增外部资源时**才修改 |

## 5. 前端依赖的后端项汇总

> 本章仅说明**前端卡在哪里**，不构成对后端的任务分配。所有需求的完整定义见《后端接口规范 v1.0》。

### 5.1 现状可用，无需后端改动（2 个）

`GET /auth/public-key`、`POST /auth/forgot-password`（空壳接口，设计文档 2.3 已将邮件发送列为后置）。

### 5.2 需要后端改造（4 项）

| 依赖项 | 接口 | 用在哪 | 不改的后果 |
|---|---|---|---|
| 登录 / 注册返回 token | `POST /auth/login`、`/register` | `shared.js` 的 Bearer 注入与 401 处理 | 无法实现真鉴权，登出只是清本地 |
| 发帖鉴权来源 | `POST /posts` 改为从 token 解析 `userId` | 发帖 | 现状信任请求体 `userId`，可冒用他人身份 |
| 信息流分页 + scope | `GET /posts` 加 `scope`、`offset/limit` | 首页分页、关注流 | 只能拿固定最新 50 条 |
| 列表响应结构 | `GET /posts` 由裸数组改为分页包装 | 所有列表页 | 前端需额外兼容两种格式（**最大风险点**） |
| 帖子响应增字段 | `PostResponse` 加 `liked` / `mine` / `authorAvatarUrl` | 点赞态、删除按钮显隐、头像 | 前端得自行比对 `userId`；头像只能显示首字母 |

### 5.3 需要后端新增（19 个）

| Phase | 接口 | 缺失后果 |
|---|---|---|
| M1 | `POST /auth/logout` | 登出只能清本地，服务端 token 不失效 |
| M1 | `GET /posts/{id}` | 详情页无数据 |
| M1 | `DELETE /posts/{id}` | 无删除能力 |
| M2 | `POST` / `DELETE /posts/{id}/like` | 点赞只能停在本地假状态 |
| M2 | `GET` / `POST /posts/{id}/comments` | 评论区无内容、无法评论 |
| M2 | `DELETE /comments/{id}` | 无法删自己的评论 |
| M3 | `GET /users/{id}` | 个人主页无数据 |
| M3 | `GET /users/{id}/posts` | 主页帖子区无数据 |
| M3 | `POST` / `DELETE /users/{id}/follow` | 关注流无法工作 |
| M3 | `GET /users/{id}/followers`、`/following` | 粉丝 / 关注列表无法展示 |
| M4 | `GET /search` | 搜索只能过滤当前页内存数据 |
| M4 | `GET /notifications` | 通知页无数据，角标只能硬编码 |
| M4 | `POST /notifications/read` | 未读数无法清零 |
| M4 | `GET` / `PUT /users/me` | 资料编辑不可用，只能靠登录时的缓存 |

### 5.4 无后端依赖的阶段

**Phase 0 与 Phase 5 完全不依赖后端接口的推进**。Phase 1–4 依赖 mock 层即可独立完成与验收。

## 6. `shared.js` 导出清单（步骤 0.1 的展开）

| 分类 | 导出项 |
|---|---|
| 常量 | `API_BASE`、`USE_MOCK`、`PAGE_SIZE`（20）、`MAX_POST_LENGTH`（500） |

## 8. 开工顺序

```
Phase 0 ──评审──> Phase 1 ──评审──> Phase 2 ──评审──> Phase 3 ──评审──> Phase 4 ──评审──> Phase 5
  ↑                                                                                    ↑
零后端依赖，可立即开工                                                        需后端全部就绪
```

**推荐一次做完 Phase 0，再逐阶段推进。**

理由：Phase 0 是唯一零后端依赖、且完成后每个后续阶段都能在 mock 下独立跑通并交付评审的阶段。跳过它直接写页面，会导致 4 个新页面各抄一遍工具函数与网络层，后续必须回头重构。

|---|---|
| M1 核心闭环 | Phase 0 + Phase 1 |
| M2 互动 | Phase 2 |
| M3 社交 | Phase 3 |
| M4 发现与触达 | Phase 4 |
| 收尾 | Phase 5 |
