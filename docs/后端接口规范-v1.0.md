# Chirp 后端接口规范 v1.0

| 项 | 值 |
|---|---|
| 版本 | v1.0 |
| 日期 | 2026-10-09 |
| 状态 | 待后端确认 |
| 提出方 | 前端 |
| 依据 | 《Chirp 社交平台功能设计文档》v1.0 第 4 / 7 / 8 / 9 章 |
| 适用范围 | 前端 MVP 全部页面的接口依赖；覆盖设计文档第 7 章列出的 25 个接口 |

## 本文档的约束力

1. 本文档是**前端唯一依赖的接口契约**。前端代码（含 mock 层）严格按本文档实现。
2. 后端实现与本文档不一致时，**以本文档为准**。若确需变更，走第 7 章的变更流程，前端同步升版本并改 mock。
3. 标记含义：
   - `[现状]` 后端已实现，前端可直接使用，无需改动
   - `[改造]` 后端已实现，但响应体或鉴权来源需调整
   - `[新增]` 后端尚未实现
4. 全文所有「前端行为」描述均为**规范的一部分**：后端只要满足响应契约，前端行为即自动成立；反之不成立。

## 1. 全局约定

### 1.1 基础

| 项 | 约定 |
|---|---|
| Base URL | `http://localhost:8080/api`（开发环境，经 `chirp-gateway` 转发） |
| 请求头 | `Content-Type: application/json`（有请求体时）、`Accept: application/json` |
| 字符编码 | UTF-8 |
| 跨域 | 网关层已配置，仅放行 `http://localhost:4173`；前端不处理 CORS |

### 1.2 字段命名与类型

| 项 | 约定 |
|---|---|
| 字段命名 | JSON 字段一律 `camelCase`（与后端 Java 字段一致，不做下划线转换） |
| ID | 64 位整数，JSON number。[假设] 自增主键不会超过 JS 安全整数上限 2^53-1；若未来改用雪花 ID 必须改为 string |
| 时间 | ISO-8601 带时区的 UTC 字符串，例 `2026-10-09T02:45:16.000Z`。**必须禁用时间戳数字格式**（Spring Boot 默认已禁用 `WRITE_DATES_AS_TIMESTAMPS`）。前端统一转本地时区展示 |
| 可空字段 | 一律返回 `null`，**不允许省略字段**。前端按固定 schema 解析，缺字段会视为契约违约 |
| 计数字段 | 始终返回数字，无数据返回 `0`，**不返回 null** |
| 字符串裁剪 | 后端入库前对 `content`、`name`、`bio`、`comment` 做 `trim()`；响应返回裁剪后的值 |

### 1.3 鉴权

- 除标注「鉴权：否」的接口外，一律要求请求头 `Authorization: Bearer <token>`。
- token 由 `POST /auth/login` 与 `POST /auth/register` 下发：**64 位随机字符串**，有效期 **7 天**，落 `tokens` 表。
- token 缺失 / 无效 / 过期 → `401` + `{"message":"登录已失效，请重新登录"}`。
- **硬要求**：服务端必须从 token 解析当前用户 ID。**不得信任请求体或查询参数中的 `userId`**。
- 前端行为：收到 `401` → 清空本地 `chirpToken` 与 `chirpUser` → 跳转 `/index.html?next=<当前页相对路径>` → 登录成功后回跳 `next`。

### 1.4 统一错误响应

所有非 2xx 响应体统一为：

```json
{ "message": "人类可读的中文原因" }
```

| 状态码 | 语义 | 前端行为 |
|---|---|---|
| 400 | 参数校验失败 / 业务规则拒绝（如自己关注自己） | 若为表单类请求，把 `message` 展示在对应字段下方；否则 toast 提示 |
| 401 | 未登录 / token 失效 | 清 storage → 跳登录页并带 `?next=` |
| 403 | 已登录但无权限（如删除他人帖子） | toast 提示，**不跳转** |
| 404 | 资源不存在 | 展示空态或 404 区块 |
| 409 | 唯一性冲突（如邮箱已注册） | 把 `message` 展示在对应字段下方 |
| 500 | 服务端异常 | toast「服务暂时不可用，请稍后重试」 |

- `message` 必须是**面向最终用户的中文**，前端直接展示，不做二次翻译、不拼接前缀。
- `204 No Content` 视为成功，响应体为空。前端 `request()` 对 204 返回 `null`。

### 1.5 分页

**请求参数**

| 参数 | 类型 | 默认 | 约束 |
|---|---|---|---|
| `offset` | int | `0` | ≥ 0，超出总数时返回空 `items` |
| `limit` | int | `20` | 1–50，**超出 50 按 50 处理**（不报错） |

**响应包装**（所有列表接口统一，不得直接返回裸数组）

```json
{
  "items": [],
  "total": 123,
  "offset": 0,
  "limit": 20,
  "hasMore": true
}
```

- `total`：符合条件的**总条数**（不受 limit 限制）
- `hasMore`：等价于 `offset + items.length < total`
- ⚠️ 这是对现状 `GET /posts`（当前直接返回数组）的**破坏性变更**，需后端确认。前端 `shared.js` 只认包装格式。

### 1.6 内容长度上限

| 字段 | 范围 | 备注 |
|---|---|---|
| 帖子正文 `content` | 1–500 字符 | 去首尾空白后非空；与 DB `ck_posts_content_length` 一致 |
| 评论 `content` | 1–500 字符 | 与 DB `ck_comments_content_length` 一致 |
| 用户昵称 `name` | 2–120 字符 | 与 DB `users.name VARCHAR(120)` 一致 |
| 用户简介 `bio` | 0–200 字符 | 与 DB `ck_users_bio_length` 一致 |
| 头像 URL `avatarUrl` | 0–500 字符 | 与 DB `users.avatar_url VARCHAR(500)` 一致 |

- 字符按 **Unicode 码点**计（Java `String.length()` 对增补字符会算 2，需用 `codePointCount`）。
- **前端校验只是体验层，后端必须独立校验**，不得依赖前端。

### 1.7 通知触发规则

- 自己给自己的帖子点赞 / 评论 → **不产生**通知。
- 关注自己 → 400 拒绝，不产生通知。
- 通知类型仅允许 `like` / `comment` / `follow`。

## 3. 接口详情

### 3.0 公共响应结构

#### `PostResponse`

```json
{
  "id": 12,
  "userId": 3,
  "authorName": "张三",
  "authorHandle": "zhangsan",
  "authorAvatarUrl": null,
  "content": "今天的日落值得一条头条",
  "createdAt": "2026-10-09T02:45:16.000Z",
  "likes": 5,
  "reposts": 0,
  "comments": 2,
  "liked": false,
  "mine": false
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 帖子 ID |
| `userId` | number | 作者 ID |
| `authorName` | string | 作者昵称 |
| `authorHandle` | string | 作者 handle（取邮箱 `@` 前缀），用于展示 `@zhangsan` |
| `authorAvatarUrl` | string \| null | [假设] 作者头像 URL；为 `null` 时前端回退到「首字母 + 哈希配色」头像。**需后端确认是否下发此字段** |
| `content` | string | 正文 |
| `createdAt` | string | ISO-8601 UTC |
| `likes` | number | 点赞数 |
| `reposts` | number | [待确认] 转发数。设计文档 2.3 已将「转发/转帖」列为**本期后置**，前端本期**不渲染**转发按钮。若后端确认本期不做，可从响应中移除 |
| `comments` | number | 评论数 |
| `liked` | boolean | 当前请求者是否已点赞。未登录时恒为 `false` |
| `mine` | boolean | 是否为当前请求者发布。用于决定是否渲染「删除」。未登录时恒为 `false` |

> 作者被删除等异常场景：`authorName` 返回 `"未知用户"`、`authorHandle` 返回 `"unknown"`，不返回 null。

#### `CommentResponse`

```json
{
  "id": 88,
  "postId": 12,
  "userId": 4,
  "authorName": "李四",
  "authorHandle": "lisi",
  "authorAvatarUrl": null,
  "content": "同意，今天的晚霞也是",
  "createdAt": "2026-10-09T03:10:00.000Z",
  "mine": false
}
```

#### `UserResponse`（公开资料，**不含 email**）

```json
{
  "id": 3,
  "name": "张三",
  "handle": "zhangsan",
  "bio": "写字的人",
  "avatarUrl": null,
  "createdAt": "2026-10-01T08:00:00.000Z",
  "postCount": 12,
  "followingCount": 5,
  "followerCount": 20,
  "followedByMe": false,
  "me": false
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `bio` | string \| null | 简介 |
| `avatarUrl` | string \| null | 头像 URL |
| `postCount` | number | 发帖数 |
| `followingCount` | number | 关注数（我关注了多少人） |
| `followerCount` | number | 粉丝数 |
| `followedByMe` | boolean | 当前请求者是否已关注该用户。未登录时恒为 `false` |
| `me` | boolean | 是否为当前请求者本人 |

#### `UserMeResponse` = `UserResponse` + `email`

仅 `GET /users/me`、`PUT /users/me` 返回，额外含 `"email": "zhangsan@example.com"`。**邮箱绝不出现在任何公开接口的响应中。**

#### `NotificationResponse`

```json
{
  "id": 5,
  "type": "like",
  "actor": { "id": 4, "name": "李四", "handle": "lisi", "avatarUrl": null },
  "postId": 12,
  "postExcerpt": "今天的日落值得一条头条",
  "commentId": null,
  "commentExcerpt": null,
  "isRead": false,
  "createdAt": "2026-10-09T03:20:00.000Z"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | 枚举：`like` \| `comment` \| `follow` |
| `actor` | object | 触发者，结构为 `{id, name, handle, avatarUrl}` |
| `postId` | number \| null | `type=follow` 时为 `null` |
| `postExcerpt` | string \| null | 帖子正文摘要（**截取前 50 字符**）。帖子已删除或 `type=follow` 时为 `null` |
| `commentId` | number \| null | 仅 `type=comment` 有值 |
| `commentExcerpt` | string \| null | 评论摘要（前 50 字符），仅 `type=comment` 有值 |
| `isRead` | boolean | 是否已读 |

### 3.1 会话与用户（`chirp-auth`）

#### 3.1.1 `GET /auth/public-key` `[现状]`

- **鉴权**：否
- **响应 200**：`{ "publicKey": "<SPKI DER 的 Base64>" }`
- 无需改动。前端用 `crypto.subtle.importKey("spki", ...)` 导入，以 RSA-OAEP(SHA-256) 加密密码。

#### 3.1.2 `POST /auth/register` `[改造]`

- **鉴权**：否
- **请求体**

```json
{
  "name": "张三",
  "email": "zhangsan@example.com",
  "password": "<RSA-OAEP 加密后的 Base64 密文>"
}
```

- **响应 201**：`AuthResponse`（见 3.1.3，与登录**完全同构**）
- **错误**

| 码 | 条件 | message |
|---|---|---|
| 400 | 昵称长度不在 2–120 | `昵称需要 2-120 个字符` |
| 400 | 邮箱格式非法 | `请输入有效的邮箱地址` |
| 400 | RSA 解密失败或明文密码长度不在 8–100 | `无效的请求，请刷新页面后重试。` |
| 409 | 邮箱已注册（忽略大小写） | `该邮箱已经注册` |

- **改造点**：现响应为 `{id, name, email, message}`，需**追加 `token`、`expiresAt`、`handle`、`avatarUrl`**（见 3.1.3 结构）。前端注册成功后直接进入登录态，不再二次登录。

#### 3.1.3 `POST /auth/login` `[改造]`

- **鉴权**：否
- **请求体**

```json
{ "email": "zhangsan@example.com", "password": "<RSA-OAEP 密文>" }
```

- **响应 200**：`AuthResponse`

```json
{
  "token": "3f8a1c9e4b7d2f6a0e5c8b1d4a7f9e2c6b3d8a1f4e7c0b5d9a2f6e3c8b1d4a7f",
  "expiresAt": "2026-10-16T02:45:16.000Z",
  "id": 3,
  "name": "张三",
  "email": "zhangsan@example.com",
  "handle": "zhangsan",
  "avatarUrl": null,
  "message": "登录成功"
}
```

| 字段 | 说明 |
|---|---|
| `token` | 64 位随机字符串，前端存 `chirpToken` |
| `expiresAt` | token 过期时间，ISO-8601 UTC |
| `id` / `name` / `email` / `handle` / `avatarUrl` | 当前用户基础信息，前端存 `chirpUser` |

- **错误**：`401` + `邮箱或密码不正确`（**不区分「邮箱不存在」与「密码错误」**，防用户枚举）
- **改造点**：① 追加 `token` / `expiresAt` / `handle` / `avatarUrl`；② 登录成功时写入 `tokens` 表（随机 64 位、7 天过期）。
- **前端行为**：勾选「记住我」→ 存 `localStorage`；否则存 `sessionStorage`。跳转 `?next=` 指定页，无 `next` 则跳 `/home.html`。

#### 3.1.4 `POST /auth/logout` `[新增]`

- **鉴权**：是
- **请求体**：无
- **响应 204**：无响应体
- **行为**：删除当前 `Authorization` 头中 token 对应的 `tokens` 记录。
- **错误**：`401` token 已失效（前端忽略该错误，直接清本地 storage 跳登录）
- **前端行为**：清 `chirpToken` 与 `chirpUser` → 跳 `/index.html`。**即使接口报错也必须完成本地清理。**

#### 3.1.5 `POST /auth/forgot-password` `[现状]`

- **鉴权**：否
- **请求体**：`{ "email": "zhangsan@example.com" }`
- **响应 200**：`{ "message": "如果该邮箱已注册，重置密码的链接将发送到你的邮箱。" }`
- 无需改动。设计文档 2.3 已明确本期不做邮件真实发送，维持现状。

#### 3.1.6 `GET /users/me` `[新增]`

- **鉴权**：是
- **响应 200**：`UserMeResponse`（`UserResponse` + `email`）
- **用途**：前端进入个人主页 / 编辑资料时拉取最新资料，避免使用可能过期的 storage 缓存。
- **错误**：`401`

#### 3.1.7 `PUT /users/me` `[新增]`

- **鉴权**：是
- **请求体**（三个字段**全部可选**，只传需要修改的；未传的字段保持不变）

```json
{ "name": "张三丰", "bio": "写字的人", "avatarUrl": "https://example.com/a.png" }
```

- **响应 200**：`UserMeResponse`
- **错误**

| 码 | 条件 | message |
|---|---|---|
| 400 | 昵称长度不在 2–120 | `昵称需要 2-120 个字符` |
| 400 | bio 超过 200 字符 | `简介不能超过 200 个字符` |
| 400 | avatarUrl 超过 500 字符 | `头像链接过长` |
| 400 | 三个字段全部未传 | `没有需要更新的内容` |
| 401 | 未登录 | `登录已失效，请重新登录` |

- **约束**：邮箱与密码本期**不可**通过此接口修改（设计文档 4.1）。请求体中出现 `email` / `password` 字段一律忽略。

#### 3.1.8 `GET /users/{id}` `[新增]`

- **鉴权**：否
- **路径参数**：`id` 用户 ID
- **响应 200**：`UserResponse`（**不含 email**）
- **错误**：`404` + `用户不存在`
- **前端行为**：个人主页据此渲染资料卡与「关注 / 取关」按钮；`me=true` 时不渲染关注按钮，改渲染「编辑资料」。

### 3.2 帖子与互动

#### 3.2.1 `GET /posts` `[改造]`

- **鉴权**：`scope=latest` 否；`scope=following` **是**
- **查询参数**

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `scope` | string | `latest` | `latest` 全站最新（访客可见）；`following` 我关注的人的帖子 |
| `offset` | int | `0` | 见 1.5 |
| `limit` | int | `20` | 见 1.5，上限 50 |

- **响应 200**：分页包装，`items` 为 `PostResponse[]`，按 `createdAt` **倒序**
- **错误**：`401` `scope=following` 但未登录 / token 失效
- **改造点**：① 响应由裸数组改为分页包装；② 支持 `scope`；③ 分页（现状固定取最新 50 条）。
- **前端行为**：`scope=following` 且 `total=0` 时展示「关注流还是静的」空态；`latest` 且 `total=0` 时展示「还没有任何鸣响」空态。

#### 3.2.2 `POST /posts` `[改造]`

- **鉴权**：是
- **请求体**

```json
{ "content": "今天的日落值得一条头条" }
```

- **响应 201**：`PostResponse`
- **错误**

| 码 | 条件 | message |
|---|---|---|
| 400 | `content` 去首尾空白后为空 | `内容不能为空` |
| 400 | `content` 超过 500 字符 | `内容不能超过 500 字符` |
| 401 | 未登录 | `登录已失效，请重新登录` |

- **改造点**：**移除请求体中的 `userId` 字段**，作者一律由 token 解析。这是硬要求 —— 现状从请求体取 `userId` 只校验其存在，任何调用方改一个数字即可冒用他人身份发帖。
- **前端行为**：请求体**只发 `content`**。成功后把响应的 `PostResponse` 插入列表头部并高亮。

#### 3.2.3 `GET /posts/{id}` `[新增]`

- **鉴权**：否
- **响应 200**：`PostResponse`
- **错误**：`404` + `帖子不存在`
- **前端行为**：未登录时 `liked` / `mine` 均为 `false`，因此不渲染删除按钮；未登录点「点赞」应跳登录页并带 `?next=/post.html?id=<id>`。

#### 3.2.4 `DELETE /posts/{id}` `[新增]`

- **鉴权**：是
- **响应 204**：无响应体
- **错误**

| 码 | 条件 | message |
|---|---|---|
| 403 | 已登录但非作者 | `只能删除自己发布的内容` |
| 404 | 帖子不存在 | `帖子不存在` |
| 401 | 未登录 | `登录已失效，请重新登录` |

- **行为**：物理删除（设计文档 12 章）。其 `comments`、`likes` 由 DB 外键 `ON DELETE CASCADE` 级联删除；关联 `notifications.post_id` 由 `ON DELETE SET NULL` 置空。
- **前端行为**：详情页与首页的删除按钮**必须二次确认**；成功后回首页并刷新列表。

#### 3.2.5 `GET /users/{id}/posts` `[新增]`

- **鉴权**：否
- **查询参数**：`offset` / `limit`，见 1.5
- **响应 200**：分页包装，`items` 为 `PostResponse[]`，按 `createdAt` 倒序
- **错误**：`404` + `用户不存在`

#### 3.2.6 `POST /posts/{id}/like` `[新增]`

- **鉴权**：是
- **响应 200**

```json
{ "liked": true, "likes": 6 }
```

- **错误**：`404` `帖子不存在`；`401`
- **幂等**：重复点赞**不报错**，仍返回 `200` + `liked: true` + 最新 `likes`。
- **约束**：DB 唯一约束 `uk_likes_user_post` 保证一人一帖一赞。
- **前端行为**：先乐观更新 UI，请求失败则回滚并 toast；以响应中的 `likes` 为准覆盖本地值。

#### 3.2.7 `DELETE /posts/{id}/like` `[新增]`

- **鉴权**：是
- **响应 200**：`{ "liked": false, "likes": 5 }`
- **错误**：`404` `帖子不存在`；`401`
- **幂等**：未点赞时取消**不报错**，返回 `200` + `liked: false` + 最新 `likes`。

#### 3.2.8 `GET /posts/{id}/comments` `[新增]`

- **鉴权**：否
- **查询参数**：`offset` / `limit`，见 1.5
- **响应 200**：分页包装，`items` 为 `CommentResponse[]`，按 `createdAt` **升序**（评论区阅读习惯，与帖子列表的倒序相反）
- **错误**：`404` `帖子不存在`

#### 3.2.9 `POST /posts/{id}/comments` `[新增]`

- **鉴权**：是
- **请求体**：`{ "content": "同意，今天的晚霞也是" }`
- **响应 201**：`CommentResponse`
- **错误**

| 码 | 条件 | message |
|---|---|---|
| 400 | 内容为空 | `评论不能为空` |
| 400 | 超过 500 字符 | `评论不能超过 500 字符` |
| 404 | 帖子不存在 | `帖子不存在` |
| 401 | 未登录 | `登录已失效，请重新登录` |

- **副作用**：帖子作者 ≠ 评论者时，写一条 `type=comment` 的 `notifications` 记录。

#### 3.2.10 `DELETE /comments/{id}` `[新增]`

- **鉴权**：是
- **响应 204**：无响应体
- **错误**：`403` `只能删除自己发布的内容`；`404` `评论不存在`；`401`
- **副作用**：关联 `notifications.comment_id` 由 `ON DELETE SET NULL` 置空。

#### 3.2.11 `GET /search` `[新增]`

- **鉴权**：否
- **查询参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `q` | string | 是 | 关键词；`trim` 后为空 → 400 |
| `type` | string | 是 | `post` 或 `user`，其他值 → 400 |
| `offset` / `limit` | int | 否 | 见 1.5 |

- **响应 200**：分页包装
  - `type=post`：`items` 为 `PostResponse[]`，匹配 `posts.content ILIKE '%q%'`，按 `createdAt` 倒序
  - `type=user`：`items` 为 `UserResponse[]`，匹配 `users.name ILIKE '%q%'`
- **错误**：`400` `搜索关键词不能为空` / `搜索类型不合法`
- **前端行为**：搜索页**并发发起两个请求**（`type=post` 与 `type=user`），分区展示。此设计遵循设计文档 7.2 的接口定义，未额外引入 `type=all`。

### 3.3 社交与通知

#### 3.3.1 `POST /users/{id}/follow` `[新增]`

- **鉴权**：是
- **响应 200**：`{ "following": true, "followerCount": 21 }`
- **错误**

| 码 | 条件 | message |
|---|---|---|
| 400 | 关注自己 | `不能关注自己` |
| 404 | 目标用户不存在 | `用户不存在` |
| 401 | 未登录 | `登录已失效，请重新登录` |

- **幂等**：重复关注不报错，返回 `200` + `following: true` + 最新 `followerCount`。
- **副作用**：写一条 `type=follow` 的 `notifications` 记录。

#### 3.3.2 `DELETE /users/{id}/follow` `[新增]`

- **鉴权**：是
- **响应 200**：`{ "following": false, "followerCount": 20 }`
- **错误**：`404` `用户不存在`；`401`
- **幂等**：未关注时取关不报错。
- **副作用**：**不删除**已产生的 follow 通知（设计文档未要求回溯）。

#### 3.3.3 `GET /users/{id}/followers` `[新增]`

- **鉴权**：否
- **查询参数**：`offset` / `limit`，见 1.5
- **响应 200**：分页包装，`items` 为 `UserResponse[]`，按关注时间倒序
- **错误**：`404` `用户不存在`

#### 3.3.4 `GET /users/{id}/following` `[新增]`

- **鉴权**：否
- **响应 200**：分页包装，`items` 为 `UserResponse[]`，按关注时间倒序
- **错误**：`404` `用户不存在`

#### 3.3.5 `GET /notifications` `[新增]`

- **鉴权**：是
- **查询参数**：`offset` / `limit`，见 1.5
- **响应 200**：分页包装 **+ 扩展字段 `unreadCount`**

```json
{
  "items": [],
  "total": 30,
  "offset": 0,
  "limit": 20,
  "hasMore": true,
  "unreadCount": 3
}
```

- `items` 为 `NotificationResponse[]`，按 `createdAt` 倒序
- `unreadCount`：当前用户**全部**未读通知数（不受分页影响），供导航角标使用
- **错误**：`401`
- **前端行为**：导航角标显示 `unreadCount`，为 `0` 时不显示角标。**替换现状硬编码的 "3"。**

#### 3.3.6 `POST /notifications/read` `[新增]`

- **鉴权**：是
- **请求体**

```json
{ "ids": [1, 2, 3] }
```

- `ids` 可选。**不传或传 `null` = 全部标记已读**（设计文档 4.8 的要求）。
- **响应 200**：`{ "unreadCount": 0 }`
- **错误**：`401`
- **幂等**：重复标记不报错。

## 6. 已确认的关键决策

| # | 决策 | 结论 |
|---|---|---|
| D1 | 会话机制 | DB token（设计文档 8.3），不用 JWT；token 落 `tokens` 表，7 天过期，可即时作废 |
| D2 | 帖子正文上限 | **500 字符**（与 DB `ck_posts_content_length` 一致）；前端由现状 280 改为 500 |
| D3 | 鉴权来源 | 一律从 token 解析用户，**禁止信任请求体 / 查询参数中的 `userId`** |
| D4 | 分页格式 | 统一包装 `{items, total, offset, limit, hasMore}`，`limit` 上限 50 |
| D5 | 错误体格式 | 统一 `{ "message": "<中文>" }`，前端直接展示 |

## 7. 变更流程

1. 后端发现规范不可实现或有更优方案 → **提出变更申请**，说明接口编号（如 §3.2.4）、当前约定、建议方案、理由。
2. 前端评估对已实现页面与 mock 的影响面。
3. 双方确认后，本文档**升版本号**（v1.0 → v1.1），在下方变更记录中登记。
4. 前端同步修改 `mock/` 与 `shared.js`；后端同步实现。
5. **禁止任何一方单方面偏离本文档实现**，否则联调阶段必然返工。
